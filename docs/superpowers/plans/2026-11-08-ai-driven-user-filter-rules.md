# AI-Driven Dynamic Candidate Filter Rules & Interactive Editor Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace static hardcoded archetype dictionaries with an intelligent AI extraction engine and interactive UI editor, allowing any candidate (Civil, Mechanical, Electrical, Biotech, CS, etc.) to have tailored scraper and matching filter rules extracted from their CV, customized interactively in the UI, and persisted in their profile.

**Architecture:**
- **AI Rule Extraction (`src/ai/resume_parser.py`)**: Uses Gemini via `AIRouter` to extract domain-specific `target_titles`, `inclusion_keywords`, `exclusion_keywords`, and `seniority_ceiling` from raw resume text.
- **Filter Rules Persistence & API (`src/db/database.py` & `src/dashboard/routers/jobs.py`)**: Stores user-scoped `filter_rules` in SQLite/PostgreSQL `candidate_profiles` table, exposed via `GET /api/profile/filter-rules`, `POST /api/profile/filter-rules`, and `POST /api/profile/filter-rules/ai-generate`.
- **Interactive UI Editor (`frontend/src/views/profile/filterRulesEditor.ts`)**: Interactive tag-pill component in the Candidate Profile tab allowing candidates to review, add, edit, or delete target titles, keywords, negative terms, and trigger one-click AI auto-tuning.
- **Dynamic Scraper & AI Matcher Binding (`src/scrapers/query_builder.py` & `src/core/dynamic_filters.py`)**: Directly binds scraper query generation and Gemini matching evaluations to the candidate's custom persisted filter rules rather than static hardcoded catalogs.

**Tech Stack:** Python 3.11, FastAPI, Pydantic, Gemini API (Universal AI Router), TypeScript, Vite, CSS Pills/Badges, SQLite / PostgreSQL, Vitest, Pytest.

**Spec:** Multi-User SaaS architectural requirement to support arbitrary career backgrounds dynamically via AI extraction and user self-service configuration without manual code edits or hardcoded keyword tables.

## Global Constraints
- **Zero Hardcoded Presets**: Filter keywords and target titles must originate from the candidate's CV and interactive user edits, never hardcoded static lists.
- **User Agency**: The candidate must always be able to manually add, edit, or remove any keyword, title, or exclusion generated by the AI.
- **Admin Compatibility**: Toyanath Pandey (User ID 1 / Admin) retains verified CS and data engineering profile rules as default fallback.
- **Universal Spam Isolation**: Universal non-job spam (e.g. `initiativbewerbung`, `talents wanted`, `quereinsteiger`, `call center`) remains blocked globally while respecting discipline-specific terminology.

## Review Focus
1. **Civil Engineer CV**: AI extracts `["Bauingenieur", "Statiker", "Tragwerksplaner"]` and keywords `["AutoCAD", "BIM", "Statik"]` into editable UI tags without any Python/CS keywords.
2. **Interactive Customization**: Adding a new title tag `Geotechniker` or negative keyword `Dachdecker` saves instantly to the database and appears in subsequent scraper queries.
3. **AI Auto-Tune Trigger**: Clicking "⚡ Auto-Tune from Resume" dynamically analyzes the candidate's existing resume text and refreshes the filter tags.
4. **Scraper Query Generation**: Scrapers (LinkedIn, Bund, XING, BA) query specifically for the candidate's active custom titles.
5. **Pre-Filter Execution**: Jobs matching user's custom exclusion keywords are rejected before calling paid AI APIs.
